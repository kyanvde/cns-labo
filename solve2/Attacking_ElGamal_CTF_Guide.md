## ElGamal in one page

ElGamal's security rests on the discrete logarithm problem (DLP): given $g$ and $h = g^x \bmod p$, finding $x$ is hard in a large, well-chosen group. It comes in two separate schemes that share a key but are attacked differently — don't mix them up.

**Encryption**

- Key: private $x$, public $(p, g, h)$ with $h = g^x \bmod p$
- Encrypt $m$: pick a nonce $k$, send $c_1 = g^k$, $c_2 = m\cdot h^k$
- Decrypt: $m = c_2\cdot(c_1^x)^{-1} \bmod p$

The shared secret $h^k = c_1^x$ is just Diffie–Hellman. Breaking DH here breaks encryption.

**Signature (different scheme!)**

- Sign $m$: pick $k$ with $\gcd(k, p-1) = 1$
- $r = g^k \bmod p$
- $s = (H(m) - x\cdot r)\cdot k^{-1} \bmod (p-1)$
- Verify: $0 < r < p$ and $g^{H(m)} \equiv y^r\cdot r^s \pmod p$

Note the two different moduli: group math is mod $p$, exponent math is mod $p-1$.

> **The modulus trap:** in signatures, everything in an exponent (computing $s$, $k$, $x$) is mod $p-1$, which is even and therefore not a field. Inverses mod $p-1$ often don't exist; you need a gcd-aware division (shown in attack 09). Group elements ($r$, $c_1$) are mod $p$.

## A. Breaking the key (discrete log)

If you can solve the DLP and recover the private $x$, you decrypt everything and can sign anything. These attacks exploit a badly chosen group — the single most common ElGamal mistake.

### 01 Why the group matters

**When to suspect it**

- Any ElGamal challenge — this frames the next three

**Why it works**

Everything rests on the DLP being hard in the group generated by $g$. It's hard only when that group has a large prime factor in its order. Generic DLP algorithms cost about $\sqrt{\text{largest prime factor of the order}}$, so a 256-bit prime order is safe but a 256-bit order that factors into 32-bit pieces is not. Secure practice: a safe prime $p = 2q + 1$ with $g$ of prime order $q$. CTF challenges break exactly this.

### 02 Baby-step giant-step (small groups)

**When to suspect it**

- $p$ is small (≲ 60 bits), or $g$ only generates a small subgroup
- The whole challenge is small enough to brute force in meet-in-the-middle time

**Why it works**

BSGS solves $g^x = h$ in $\sqrt{n}$ time and $\sqrt{n}$ memory, where $n$ is the order of $g$. Write $x = i\cdot m + j$ with $m = \lceil\sqrt{n}\rceil$. Precompute all $g^j$ (baby steps) into a table, then walk $h\cdot g^{-im}$ (giant steps) until one lands in the table. It's the DLP analogue of meet-in-the-middle.

```python
def bsgs(g, h, p, order=None):
    # solve g^x = h (mod p); order = order of g (defaults to p-1)
    n = order or (p - 1)
    m = isqrt(n) + 1
    table = {}
    e = 1
    for j in range(m):
        table[e] = j
        e = e * g % p
    factor = pow(g, -m, p)          # g^(-m)
    gamma = h
    for i in range(m + 1):
        if gamma in table:
            return i * m + table[gamma]
        gamma = gamma * factor % p
    return None
```

> **Watch out:** memory is the limit: ~$\sqrt{n}$ entries. Past ~$2^{50}$ you need Pollard's rho for DLP (constant memory, same time) or Pohlig-Hellman.

### 03 Pohlig–Hellman (smooth $p - 1$)

**When to suspect it**

- `factorint(p-1)` returns only small primes
- $p$ itself is large, so BSGS alone looks hopeless — but the order isn't really big

**Why it works**

If the group order $n = p-1$ factors as $\prod q_i^{e_i}$ with small $q_i$, you don't solve one big DLP — you solve one small DLP in each prime-power subgroup and glue the answers with CRT. You recover $x \bmod q_i^{e_i}$ by projecting into the subgroup of size $q_i^{e_i}$ (raise to the $n / q_i^{e_i}$ power), then BSGS there. Total cost is about $\sqrt{\text{largest } q_i}$ — tiny when $p-1$ is smooth, even for a 2048-bit $p$.

```python
def _crt(rs, ms):
    M = 1
    for m in ms: M *= m
    x = 0
    for r, m in zip(rs, ms):
        Mi = M // m
        x += r * Mi * pow(Mi, -1, m)
    return x % M

def pohlig_hellman(g, h, p, order_factors=None):
    # discrete log of h base g in Z_p*; works fast when p-1 is smooth
    n = p - 1
    facs = order_factors or factorint(n)
    residues, moduli = [], []
    for q, e in facs.items():
        pe = q ** e
        gi = pow(g, n // pe, p)
        hi = pow(h, n // pe, p)
        xi = bsgs(gi, hi, p, order=pe)   # small DLP in subgroup of size q^e
        residues.append(xi); moduli.append(pe)
    return _crt(residues, moduli)
```

> **Watch out:** this is why real ElGamal demands a safe prime. If even one large prime divides $p-1$ you're stuck at that subgroup; combine with index calculus if it's moderate.

### 04 Index calculus (medium primes)

**When to suspect it**

- $p$ is 100+ digits, $p-1$ is not smooth, but $p$ is still well under 1024 bits
- Pure DLP with no structural shortcut

**Why it works**

The sub-exponential algorithm for prime-field DLP, the analogue of the number field sieve for factoring. It finds logarithms of a factor base of small primes by collecting smooth relations, then expresses your target in terms of them. You don't implement it by hand; Sage's `discrete_log` switches to it automatically, and it's the reason 512-bit ElGamal is breakable with effort. For $p$ up to ~400 bits Sage will often just solve it.

```python
# SageMath: one line discrete log, picks the best algorithm itself
p = ...; g = ...; h = ...
F = GF(p)
x = discrete_log(F(h), F(g))        # h = g^x
# subgroup order known? discrete_log(F(h), F(g), ord=q) is much faster
```

## B. Encryption weaknesses

Here the group is fine, but how the encryption is used leaks the message. None of these solve the DLP.

### 05 Nonce ($k$) reuse

**When to suspect it**

- Two ciphertexts share the same $c_1$ (so the same $k$ was used)
- A known or guessable plaintext is sent alongside the secret one

**Why it works**

$c_1 = g^k$ depends only on $k$, so an identical $c_1$ is a dead giveaway. Then both messages are masked by the same $h^k$: $c_2 = m\cdot h^k$. Dividing two ciphertexts cancels the mask, $c_2/c_2' = m/m'$, so one known plaintext reveals the other. You never learn $k$ or $x$ — you don't need to.

```python
def k_reuse_enc(c2_known, m_known, c2_target, p):
    # same k used twice (c1 identical). Recover m_target from a known plaintext.
    # c2 = m * h^k, so m_target = m_known * c2_target / c2_known
    return m_known * c2_target % p * pow(c2_known, -1, p) % p
```

> **Watch out:** messages must be $< p$ to survive mod $p$. If $m$ was byte-encoded longer than $p$ it was split or wrapped; mirror that.

### 06 Legendre symbol leak (semantic insecurity)

**When to suspect it**

- The scheme encrypts a single bit, or you only need one bit of $m$ (e.g. a yes/no, a coinflip)
- $g$ is a full generator of $\mathbb{Z}_p^*$ (not restricted to the QR subgroup)

**Why it works**

Textbook ElGamal is not semantically secure: it always leaks whether $m$ is a quadratic residue. The Legendre symbol is multiplicative, so $\left(\frac{c_2}{p}\right) = \left(\frac{m}{p}\right)\cdot\left(\frac{h}{p}\right)^k$. If $g$ is a generator then $\left(\frac{g}{p}\right) = -1$, so $\left(\frac{c_1}{p}\right) = (-1)^k$ hands you $k \bmod 2$. With $\left(\frac{h}{p}\right)$ public, you solve for $\left(\frac{m}{p}\right)$ — one guaranteed bit of every message, no key needed.

```python
def legendre_leak(c1, c2, p, g, h):
    # recovers the Legendre symbol of m (one bit: is m a QR?)
    # valid when g is a generator of Z_p* (so legendre(g) = -1)
    lk = 0 if legendre(c1, p) == 1 else 1   # k mod 2, since legendre(c1)=(-1)^k
    lh = legendre(h, p)                      # publicly computable
    return legendre(c2, p) * (lh ** lk)      # = legendre(m)
```

> **Watch out:** the fix (and the defence to recognise) is working in the prime-order QR subgroup, where every element is a residue and this bit carries no information.

### 07 Malleability and CCA

**When to suspect it**

- There's a decryption oracle that refuses one target ciphertext
- You can modify a ciphertext in transit and care what the plaintext becomes

**Why it works**

ElGamal is homomorphic: multiplying $c_2$ by $t$ turns an encryption of $m$ into an encryption of $m\cdot t$, with $c_1$ untouched. Against a decryption oracle that blacklists the challenge ciphertext, send $(c_1, c_2\cdot t)$, get back $m\cdot t$, and divide by $t$. The same property means an attacker can silently scale a plaintext — a problem whenever $m$ is a number with meaning (a balance, a vote).

```python
def maul(c1, c2, factor, p):
    # ElGamal is homomorphic: this yields a valid encryption of m*factor
    return c1, c2 * factor % p

# ---- signatures ----
# Sign(m): r = g^k, s = (H(m) - x*r) * k^-1 mod (p-1), with gcd(k,p-1)=1
# Verify: 0 < r < p and g^H(m) == y^r * r^s (mod p)
def eg_verify(p, g, y, H, r, s):
    if not (0 < r < p): return False
    return pow(g, H, p) == pow(y, r, p) * pow(r, s, p) % p
```

## C. Signature weaknesses

The ElGamal signature scheme is fragile in exactly the way DSA is. The per-signature nonce $k$ is the crown jewel: anything you learn about it collapses to the private key.

### 08 Nonce reuse → private key

**When to suspect it**

- Two signatures have the same $r$ (identical nonce $k$)
- A signing oracle with a broken/fixed RNG

**Why it works**

Equal $r$ means equal $k$. Subtracting the two $s$ equations kills $x$: $s_1 - s_2 = (H_1 - H_2)\cdot k^{-1}$, giving $k = (H_1 - H_2)/(s_1 - s_2) \bmod (p-1)$. Then back-substitute into $s\cdot k = H - x\cdot r$ to get $x = (H - s\cdot k)\cdot r^{-1}$. Full key recovery from two signatures — the exact flaw that broke the Sony PS3.

```python
def _div_mod(a, b, m):
    # solve b*x = a (mod m) when gcd(b,m) may be > 1; returns one solution
    g = gcd(b, m)
    if a % g: return None
    a, b, m = a // g, b // g, m // g
    return a * pow(b, -1, m) % m

def sig_nonce_reuse(p, r, s1, s2, H1, H2):
    # same k (=> same r) on two messages -> recover k, then private x
    order = p - 1
    k = _div_mod((H1 - H2) % order, (s1 - s2) % order, order)
    x = _div_mod((H1 - s1 * k) % order, r, order)   # from s*k = H - x*r
    return k, x
```

> **Watch out:** $p-1$ is even, so $r$ and $(s_1-s_2)$ may not be invertible mod $(p-1)$. Use the gcd-aware `div_mod` helper; it may yield a few candidates when gcd>1 — test each against a known signature.

### 09 Known or predictable nonce

**When to suspect it**

- $k$ is small enough to brute force, or comes from a weak/seeded RNG, or is reused as a counter
- Any partial leak of $k$

**Why it works**

One equation, one unknown: $s = (H - x\cdot r)\cdot k^{-1}$ rearranges to $x = (H - s\cdot k)\cdot r^{-1} \bmod (p-1)$. A single signature with a known $k$ gives up $x$ immediately. If $k$ is merely small, brute-force it; if only some bits leak, lattice methods (as for ECDSA) finish the job.

```python
def sig_known_k(p, r, s, H, k):
    # k leaked/predictable -> private x = (H - s*k) * r^-1 mod (p-1)
    order = p - 1
    return _div_mod((H - s * k) % order, r, order)
```

### 10 Existential forgery (no hash)

**When to suspect it**

- The verifier checks `g^m ≡ y^r · r^s` with the raw message $m$, no hash $H$
- A textbook/teaching implementation

**Why it works**

Signing the raw message instead of $H(m)$ is forgeable without the key. Pick any $e$, $v$, set $r = g^e\cdot y^v \bmod p$. The verification $g^m = y^r\cdot r^s$ becomes solvable: choose $s = -r\cdot v^{-1}$ and $m = e\cdot s \bmod (p-1)$, and it verifies. You don't control $m$ (hence existential), but for an unprotected scheme that's already a break. A cryptographic hash stops it because you can't steer $m$ to a chosen $H$.

```python
def existential_forgery(p, g, y, e=2, v=3):
    # no-hash ElGamal: forge a valid (r,s) for SOME message m (not chosen)
    order = p - 1
    r = pow(g, e, p) * pow(y, v, p) % p       # r = g^e * y^v
    s = (-r * pow(v, -1, order)) % order      # s = -r / v
    m = (e * s) % order                       # the message it signs
    return m, r, s
```

### 11 Missing range check (Bleichenbacher)

**When to suspect it**

- The verifier never checks $0 < r < p$, accepting $r$ values outside the range
- Often paired with $g \mid (p-1)$

**Why it works**

If the verifier accepts an out-of-range $r$ (e.g. a value reduced only mod $p$ but reconstructed mod $p(p-1)$ via CRT), you can craft $r$ to satisfy verification for a chosen message without the key. The construction uses CRT to force $r$ to be a known power mod $p$ and whatever is needed mod $p-1$. It's fiddly and situational — the practical lesson is to recognise it: always confirm the implementation enforces $0 < r < p$. A verifier that doesn't is forgeable.

## Defences: how ElGamal is used safely

| Mistake in the challenge | What correct use does |
| --- | --- |
| Smooth $p-1$, small-order $g$ (Pohlig–Hellman, BSGS) | Safe prime $p = 2q + 1$, $g$ of large prime order $q$ |
| Raw textbook encryption (Legendre leak, malleability) | Work in the prime-order QR subgroup; add a KDF + authenticated symmetric layer (hybrid / "hashed ElGamal") |
| Reused or predictable $k$ | Fresh cryptographically random $k$ every time (or deterministic per RFC 6979) |
| Signing raw $m$, no range check | Sign $H(m)$ with a strong hash; verify $0 < r < p$. Better: use a modern scheme (Ed25519) |
| ElGamal encryption for signatures or vice versa | They are different schemes; never share structure or keys loosely |

### Python pitfalls checklist

- Group elements are mod `p`; signature exponent math (`s`, `k`, `x`) is mod `p-1`. Mixing them is the #1 bug.
- `p-1` is even, so `pow(a, -1, p-1)` fails whenever `gcd(a, p-1) > 1`. Use a gcd-aware division and test the candidates.
- Messages must be smaller than `p` or they don't survive mod `p`. Check `m < p`.
- `pow(c1, -x, p)` does the inverse-and-power in one step (Python 3.8+); don't hand-roll it.
- For discrete logs, always pass the subgroup order if you know it — it turns $\sqrt{p-1}$ into $\sqrt{\text{order}}$.
- Garbage output usually means the wrong modulus (`p` vs `p-1`) or a non-generator `g`.
